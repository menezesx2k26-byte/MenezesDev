# 1. Governing portfolio rule

- approximately 70% SEO/AdSense opportunity;
- approximately 20% architectural coverage;
- approximately 10% experimentation.

This recommendation uses an exact working allocation:

- **35 SEO/AdSense-led tools (70%)**;
- **10 architectural-coverage tools (20%)**;
- **5 experiments/strategic bets (10%)**.

Every recommended tool:

- has an independent useful intent;
- has a concrete Phase-3 path;
- is browser/local for ordinary processing;
- requires 0 MenezesDev backend processing requests per ordinary operation;
- is compatible with the approved English-primary/PT-BR-secondary model;
- has no HOLD/UNRESOLVED capability dependency.

Only **4/50** recommended tools retain a local-conditional admission gate; all four have exact conditions already documented.

# 6. Replacement policy before implementation

If a recommended conditional tool fails its exact admission gate before implementation, do **not** weaken the gate.

Replacement order should prefer the closest high-confidence reserve that:

- preserves portfolio balance;
- uses an already-approved/local engine;
- has independent intent;
- does not introduce a new hard-stop dependency/backend boundary.

Examples:

- PDF conditional failure → Replace with Remove PDF Pages only if the shared engine itself remains admitted; otherwise use a clear/local non-PDF reserve.
- Image Compressor benchmark failure → promote a clear local image/math/developer reserve rather than uploading images to a server.
- HTML Formatter dependency failure → promote XML Formatter or another clear developer reserve.
