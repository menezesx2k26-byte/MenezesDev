# 6. Replacement policy before implementation

If a recommended conditional tool fails its exact admission gate before implementation, do **not** weaken the gate.

Replacement order should prefer the closest high-confidence reserve that:

- preserves portfolio balance;
- uses an already-approved/local engine;
- has independent intent;
- does not introduce a new hard-stop dependency/backend boundary.

Examples:

- PDF engine admission failure → do not substitute another unsafe PDF parser; promote a clear/local non-PDF reserve instead.
- Image Compressor benchmark failure → promote a clear local image/math/developer reserve rather than uploading images to a server.
- HTML Formatter dependency failure → promote XML Formatter or another clear developer reserve.
